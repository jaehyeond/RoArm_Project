User wants PROBLEM-DRIVEN research framing, not metrics-improvement papers.

**Why**: Supervisor explicitly criticized "just picking up sponges" — the core issue is that the research question is too narrow, not that the hardware is too simple. Research must answer a real-world question that someone outside robotics cares about.

**How to apply**: Every paper section should be written with the "who has this problem in the real world?" question answered explicitly. Introduction should not start with "VLA methods have improved performance on benchmark X." Start with a real pain point.

---

Do not write papers that:
- Claim improved metrics on existing benchmarks without a real-world problem context
- Are pure ablation studies without a story
- Claim "first" without 10+ verification searches first

**Why**: User stated this explicitly and the 2026-03-10 incident reinforced it — false novelty claims damage credibility with reviewers.
