# VLA & Foundation Models for Robotics: Intelligence Report

**Agent: VLA-INTEL | Date: 2026-03-07 | Classification: Comprehensive**

---

## Executive Summary

The VLA (Vision-Language-Action) landscape has exploded since mid-2024. As of early 2026, there are **15+ significant VLA/foundation models** for robotics, ranging from 93M to 55B parameters. The field is converging on a clear architecture pattern: **pretrained VLM backbone + diffusion/flow-matching action head**. The most important finding for a master's student with an RTX 4090 (16GB): **SmolVLA (450M) and Octo (93M) are the only models fully trainable on consumer hardware. OpenVLA-OFT (7B) is fine-tunable via LoRA/quantization on 16GB.**

### Key Trends (Early 2026)

1. **Diffusion/Flow-matching action heads are winning** over discrete action tokenization (RT-2 style)
2. **Smaller models are catching up**: SmolVLA (450M) matches 7B+ models on benchmarks
3. **Open-loop chunked execution** outperforms closed-loop per-step in practice
4. **Cross-embodiment pretraining works** but OOD embodiment still needs 100-200+ episodes
5. **Real deployment remains rare**: Only pi-0/pi-0.5 and a few startups run VLAs in production
6. **Data quality > quantity**: 50 good episodes beats 500 bad ones

### 1. SmolVLA (HuggingFace / LeRobot)

| Attribute | Details |
|-----------|---------|
| **Paper** | arXiv:2506.01844 (Jun 2025) |
| **Organization** | Hugging Face |
| **Parameters** | **450M** total (~250M VLM + ~200M Action Expert) |
| **Architecture** | SmolVLM-2 (SigLIP vision encoder + SmolLM2 language decoder) + Flow Matching Action Expert with interleaved cross/self-attention |
| **Backbone VLM** | SmolVLM-2 (compact, multi-image/video capable) |
| **Action Head** | Flow Matching Transformer (interleaved CA + causal SA layers) |
| **Action Space** | Continuous, chunk of n actions (default n=50) |
| **Denoising Steps** | 10 flow matching steps |
| **Training Data** | 481 community datasets, 22.9K episodes, 10.6M frames (all public, community-collected) |
| **Target Robots** | SO-100, SO-101 (primary); adaptable to any via fine-tuning |
| **GPU for Training** | **Single A100 (~4hrs for 20K steps)**, trainable on consumer GPUs |
| **GPU for Inference** | Consumer GPU or even CPU |
| **Open Source** | **Fully open**: code, weights, training data, training recipe (Apache 2.0 via LeRobot) |
| **Weights** | `lerobot/smolvla_base` on HuggingFace |
| **Framework** | LeRobot (PyTorch), `lerobot-train` CLI |
| **Real Deployment** | Community users deploying on SO-100/SO-101; our project deployed on RoArm-M3 |
| **Key Innovation** | Layer skipping (use only first L/2 VLM layers), 64 visual tokens per frame, async inference stack |
| **LIBERO Score** | Competitive with 7B models (specific numbers vary by suite) |
| **Fine-tuning Data** | ~50 episodes recommended (5 positions x 10 reps), 25 confirmed insufficient |

**RTX 4090 Accessibility: EXCELLENT.** Trainable on single GPU. batch_size=64 fits in 16GB (~10GB VRAM). This is the best option for resource-constrained researchers.

**Key Technical Details:**
- VLM layers are skipped (only first N=L/2 layers used) for speed
- Visual tokens reduced to 64 per frame via pixel shuffle (no tiling)
- Action expert hidden size = 0.75x VLM hidden dimension
- Pretraining on community SO-100 data; must fine-tune for new embodiments
- Task annotations auto-generated by Qwen2.5-VL-3B when community labels were poor
- Async inference: decouples perception/prediction from action execution

## Part 3: Architecture Taxonomy

### Action Representation Approaches

| Approach | Models | Pros | Cons |
|----------|--------|------|------|
| **Discrete tokens** (autoregressive) | RT-2, OpenVLA | Simple, leverages LLM training | Slow inference, poor for continuous control |
| **FAST tokens** (compressed discrete) | pi-0-FAST, OpenVLA+FAST | 15x faster than naive discrete | Still discrete; some quality loss |
| **Flow matching** (continuous) | SmolVLA, pi-0, pi-0.5 | Fast, high quality | Requires separate action expert |
| **Diffusion** (DDPM/DDIM) | GR00T, RDT-1B, Octo, Diffusion Policy | Handles multimodality | Slower inference (many denoising steps) |
| **L1 regression** (continuous) | OpenVLA-OFT | Fastest, simplest | May not handle multimodal distributions |
| **Adaptive grids** (spatial discrete) | SpatialVLA | 3D spatial awareness | New, less validated |

### Dual-System Pattern (Emerging Standard)

```
System 2 (Slow, Semantic)     System 1 (Fast, Motor)
┌─────────────────────┐      ┌─────────────────────┐
│  Pretrained VLM      │ ──→  │  Action Expert       │
│  (Vision + Language)  │      │  (Diffusion/Flow)    │
│  ~1-7B params         │      │  ~100M-1B params     │
│  Frozen or LoRA       │      │  Trained end-to-end  │
└─────────────────────┘      └─────────────────────┘
        ↑                              ↓
   Image + Text                   Action Chunk
   + Robot State                  (50 steps)
```

Used by: SmolVLA, pi-0, GR00T N1.x, RDT-1B, OpenVLA-OFT (implicit)

## Part 4: Analysis & Recommendations

### VLA vs. Non-VLA: Current Consensus

**The emerging consensus (early 2026):**

1. **VLAs are better when language grounding matters.** If the robot must distinguish "pick up the red pepper" from "pick up the green pepper", VLA fine-tuned models consistently outperform ACT/Diffusion Policy (OpenVLA-OFT paper, ALOHA experiments).

2. **Non-VLAs are better for single-task, high-precision work.** ACT with 10 minutes of demos achieves 80-90% on fine manipulation tasks. No VLA overhead needed.

3. **VLA pretraining provides meaningful but not magical transfer.** SmolVLA pretrained vs scratch: 78.3% vs 51.7% success rate. But OOD embodiment transfer is harder than same-embodiment.

4. **Data efficiency gap is narrowing.** SmolVLA needs ~50 episodes; ACT needs ~50 demos too. The VLA advantage is in language conditioning and semantic generalization, not data efficiency per se.

5. **Closed-loop VLAs still struggle with drift.** Open-loop chunked execution (commit to trajectory, re-observe between chunks) often works better than per-step closed-loop (our own experience confirms this).

### Which VLAs Actually Work in Real Deployment?

**Tier 1: Production-level (validated in diverse real environments)**

### Recommendations for RoArm-M3 Project

Given your specific setup (RTX 4090, 16GB, RoArm-M3, Azure Kinect, SmolVLA):

1. **SmolVLA remains your best option.** It is the only open VLA designed for single-GPU training and consumer deployment. Your 100% success with open-loop 4-chunk validates this choice.

2. **GR00T N1.6 is worth evaluating.** It is open, 3B params, and uses LeRobot-compatible data format. Inference should fit in 16GB. Fine-tuning would be tight but possible with small batch size. It may offer better cross-embodiment transfer since it is pretrained on more diverse robots.

3. **OpenVLA-OFT could work via QLoRA.** The OFT recipe (continuous actions, L1 loss, action chunking) achieves SOTA. If you can fine-tune the 7B model with 4-bit quantization + LoRA, it might outperform SmolVLA. But the engineering overhead is higher.

4. **Do NOT chase pi-0.** It is closed. The published techniques (flow matching, co-training, hierarchical reasoning) are already present in open alternatives.

5. **Consider testing ACT as a baseline.** 80M params, trains in minutes, no VLM overhead. If your task does not need language grounding, ACT with 50 demos might match or beat SmolVLA with far less complexity.
