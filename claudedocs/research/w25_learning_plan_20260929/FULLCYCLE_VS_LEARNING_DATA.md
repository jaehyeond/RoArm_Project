# 무인 자동화에 전체 사이클 데이터가 필요한가 — 정리와 검산 (2026-09-29 저녁)

> 짝 문서: `LEARNING_PLAN_BRIEF.md`(용어·목표 정의), `LEARNING_PLAN_DETAILED.md`(0~6단계 계획). 이 문서의 §3 검산은 podB(PRO 6000×2) 전체 사이클 원자료 `exec_rev34_paperbox_20260929/runs/podB_pro6000x2/run_01/w13_cycle_seed460.npz` 를 메인이 직접 계산한 값이다(CPU, 원자료 읽기만). podA 원자료로 재확인 예정.

## 1. 결론

**무인 자동화 = 고정된 전체 사이클 + 위치 선택 한 지점만 학습.** 자동화 시스템은 매번 전체 사이클(촬영 → 위치 선택 → 퍼기 → 이송 → 배출 → 복귀)을 돌지만, 학습에 필요한 데이터는 **퍼내기 구간**뿐이다. 전체 사이클은 (a) 싼 데이터 셀이 맞는지 확인하는 기준점과 (b) 실물 폐루프에서 자동화가 끊김 없이 도는지 입증하는 데 쓴다.

| 사이클 구간 | 무인 자동화에서 | 학습에 필요한가 |
|---|---|---|
| 촬영 → 높이지도 | 매 사이클 실행 | 입력(상태) |
| 위치 선택 | 학습된 모델이 결정 | 결과물 자체 |
| 접근·플런지·닫기·들어올림 | 고정 경로 | **라벨이 생기는 구간** |
| 이송·배출·복귀 | 고정 경로 | 불필요(위치 선택에 따라 결과가 거의 안 바뀜 — §3 단서) |

| 전체 사이클의 쓰임 | 무엇으로 | 몇 번 |
|---|---|---|
| 싼 셀이 같은 라벨·같은 더미 변화를 내는지 검증 기준 | 2026-09-29 podA·podB 시뮬 전체 사이클 | 2회 확보 |
| 촬영→선택→퍼기→이송→배출 반복 통합 시험 | 실물 로봇(사이클 93 s) | 학습 후 폐루프에서 |
| 최종 성능(M\* 까지 횟수·시간·실패율) 입증 | 실물 폐루프 | 최소 8쌍(D497) |

## 2. 근거
1. 프로포절: 동작(잡기·퍼기·이송·놓기)은 비학습 고정 경로, 학습 대상은 "어디를 퍼면 얼마나 잡히고 어떻게 남는가"뿐.
2. 다음 퍼내기에 영향을 주는 것은 퍼낸 뒤 더미 모양이다. 이송 중 흘린 알은 상자 밖 바닥에 떨어지고(podB spill 25알 전부 상자 밖 z≈1.3 mm), 실물 운반 유출은 0~1알(2026-09-18 사용자 관찰).
3. 위치에 따라 달라지는 이송 시간은 입자 없이 경로 계산으로 구한다.

## 3. 검산(교차 검토) — podB 원자료로 직접 확인

### 3-1. 더미 모양: "들어올린 직후"와 "사이클 끝"이 같은가
구덩이 영역 = 처음 대비 들어올린 순간 3 mm 넘게 낮아진 칸(210칸, 최대 23.4 mm).

| 비교 | 구덩이 RMS | 구덩이 p95 | 최대 | 전체 지도 RMS |
|---|---|---|---|---|
| 퍼내기 효과 자체(처음 → 끝) | 11.59 mm | 18.65 mm | 20.1 mm | — |
| **들어올린 순간 → 사이클 끝(14 s 뒤)** | **1.27 mm** | **2.33 mm** | 11.9 mm | 0.79 mm |
| 운반 끝(13.64 s) → 사이클 끝 | 0.65 mm | 1.69 mm | — | — |

- 원인: 들어올린 뒤 **53알이 더미로 되돌아옴**(들어올릴 때 분류 = 모호 40·툴 안 11·비행 2). 대부분 t 9.1~12.1 s(재닫기와 이송 시작 흔들림) 동안.
- 판단: 차이는 퍼내기 효과의 약 11 %(RMS 기준)이고 실물 카메라 반복성(p95 ≈5 mm, D497)보다 작다. **"사실상 같다"가 아니라 "대체로 같다"**가 맞는 표현이다.
- 셀 설계 반영: 들어올린 뒤 바로 지우지 말고 **재닫기 + 짧은 유지/첫 이동 흔들림 구간을 거친 뒤** 남은 알을 지운다. 이 구간 길이는 전체 사이클 두 run 과 비교해 사전등록으로 정한다.
- 부수: 배출 후 툴에 남는 알 14개가 다음 사이클로 넘어간다(다음 포획의 약 2 %). 셀은 이를 지우므로 알려진 작은 차이로 기록한다.

### 3-2. 라벨 정정 — "툴 안" 분류는 들린 양의 절반도 안 된다
들어올린 순간(lift_end, t 8.93 s) 더미 최고점(41.7 mm)보다 60 mm 이상 위에 있는 알 = **832알**(≈16.9 g).

| 분류(들어올린 순간) | 개수 |
|---|---|
| 툴 안(tool_residual) | 397 |
| **모호(ambiguous) — 툴 경계 여유 2.5 mm 안이라 이렇게 분류됨** | **430** |
| 비행(in_flight) | 5 |
| 합계(물리적으로 들린 알) | **832** |

이 832알의 끝 운명: 용기 585 · 모호 164 · 더미로 되돌아옴 44 · 흘림 25 · 툴 잔류 14.

- **정정**: 앞서 "시뮬 라벨 = lift_end 툴 안(tool_residual) 개수, podB 397 vs podA 388(2 %)"라고 했는데, tool_residual 분류는 실제로 들린 양을 절반 이하로 센다. 라벨은 분류 코드가 아니라 **기하 기준("더미 위로 들린 알", 되떨어짐 구간 뒤)** 으로 정의해야 한다.
- 장비 간 일관성(397 vs 388)은 tool_residual 분류에 대해서만 확인된 것이다. 기하 기준 라벨의 장비 간 일관성은 **podA 원자료 회수 뒤 재확인**한다.
- 실물 라벨(컵 배출량)은 그대로 유효하다. 시뮬 기하 라벨과 실물 배출량의 관계(되떨어짐·흘림)는 실물 잔차 보정 대상이다.

### 3-4. podA 반영(21:1x) — 라벨 장비 간 일치 확인
| 항목 | podA(4090) | podB(PRO 6000×2) |
|---|---|---|
| lift_end 더미 위로 들린 알 | **836** | **832** |
| 그중 tool_residual 분류 | 388 | 397 |
| 되떨어짐(끝 기준) | 281 | 44 |
| 흘림 | 123 | 25 |
| 용기 | 251 | 585 |
| 운반 전 문 관절각 | 3.04° | 2.39° |

- **기하 라벨은 장비가 달라도 0.5 % 안에서 같다** → 라벨 채택 근거 확정. 분류 코드 라벨(388/397)보다도 일치가 좋다.
- 들린 뒤의 운명(되떨어짐·흘림·배출)은 문 재닫기 각도에 따라 크게 갈린다. 시뮬 문은 실물(≈1°)보다 덜 닫히므로, 셀의 다음 상태는 "들린 알을 뺀 더미"로 두고 되떨어짐은 문에 따른 별도 효과로 기록한다(실물은 문이 닫혀 되떨어짐이 작을 것 — 실물로 확인).
- 두 run 의 lift_end 구덩이 모양 차 RMS 1.93 mm·p95 3.71 mm = 시뮬 형상 라벨의 실행 간 잡음 기준(퍼내기 효과 RMS 11.8 mm).

### 3-3. 반론과 응답
| 반론 | 응답 |
|---|---|
| 이송 중 흘림이 더미에 떨어지면 다음 상태가 달라진다 | podB 흘림 25알은 전부 상자 밖. 실물 유출 0~1알 |
| 셀은 되떨어짐을 못 담는다 | 맞다(3-1). 재닫기·짧은 흔들림 구간을 셀에 넣어 해결, 두 run 과 대조해 길이 결정 |
| 이송 시간이 위치에 따라 다르면 목표(시간)에 영향 | 경로 계산으로 입자 없이 구한다 |
| 툴 잔류가 다음 사이클로 넘어간다 | 14알(≈2 %). 알려진 차이로 기록, 필요하면 특징으로 입력 |
| 무인 자동화는 결국 전체 사이클이 돌아야 증명된다 | 맞다. 그 증명은 실물 폐루프에서 한다(시뮬 전체 사이클 수천 회가 아님) |

## 4. 선행 두 논문과의 차이 — 학습 구조와 데이터 확보

> 출처: `~/Downloads/proposal_priors_package_20260929/papers/`(절·쪽 근거 포함). 인용 함정 준수: Aoshima 시뮬은 "DEM 입자 시뮬"이 아니라 AGX 다중스케일, CoDeGa 는 sim→real 선행이 아님, 잔차 GP·형상 예측은 우리 신규성이 아니라 선행에서 가져오는 것.

|---|---|---|---|

| 모델 | 딥 평균 모델 + 잔차 GP | 신경망 세계모델 | 딥러닝 예측기 + 잔차 GP |

요약: 우리는 CoDeGa 의 **학습 구조(딥 평균 + 잔차 GP)** 와 Aoshima 의 **데이터 구조(연속 퍼내기 시뮬 데이터) 및 결정 구조(형상 예측 + 앞보기)** 를 결합하고, 두 논문 모두 하지 않은 **시뮬+실물 결합**을 한다. 대신 우리 시뮬은 Aoshima 것보다 훨씬 느려 데이터 확보 비용이 가장 큰 위험이다.
