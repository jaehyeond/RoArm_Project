## 5. 코디네이터 수정 1 — 퇴화 기하 (완료)

### 무엇을 고쳤나
`arc_segment(cx,cy,r_in,r_out,a0,a1,w)` 는 a0/a1 **두 각의 점만**으로 볼록 껍질을 만든다.
- `a0=0, a1=2π` → 두 각의 좌표가 같아 정점 4개 → 납작 → 부피 0
- `a0=0, a1=π` → 정점 4개가 한 평면 → 부피 0
- 게다가 **환형은 정의상 볼록이 아니라 한 조각으로 표현 불가**

→ `ring()` 으로 **쐐기 16개 분해**. 보울의 seg_n 분해와 같은 방식.
보어는 `1/cos(π/n)` 로 키워 다각형 현이 M3 축 자리를 잠식하지 않게 했고,
기어 뿌리 원반은 외접시켜 이빨 뿌리에 반드시 닿게 했다.

| 대상 | 전 | 후 |
|---|---|---|
| 셸 허브 (L·R) | 1조각, 부피 0 | 16조각 × 2 |
| 브래킷 피벗 보스 L·R | 1조각, 부피 0 | 16조각 × 2 |
| 기어 뿌리 원반 (L·R) | 반원 2조각, 부피 0 | 16조각 × 2 |
| **조각 수** | 224 | **345** |
| **질량 효과** | — | **+18.43 g** |

### 게이트 정정
- `all_pieces_convex` 가 `m.volume > 1e-9` 로 부피 0 을 **건너뛰고 있었다** → 위반으로 센다.
- 별도 게이트 `pieces_have_positive_volume` 신설 (원인이 달라 진단이 갈린다).

### 🔴 정정하다 드러난 것 3건 (전부 부피 0 때문에 안 보이던 것)

1. **셸 허브와 브래킷 피벗 보스가 완전히 같은 환형이었다** (둘 다 r 1.5~4, 같은 Z).
   실체화하면 두 부품이 서로 파고든다. 보스가 고정 축(부시)이고 셸이 그 위를 도는 것이
   맞으므로 허브를 **보스 바깥의 보어 랜드**(r 4.6~6.1)로 옮겼다. 셸 크랭크 슬리브가
   쓰는 규약과 동일하다. 러닝핏 `pivot_bore_clear_mm` 0.25 → **0.6 mm**
   (0.25 는 FDM 공차로 뻑뻑하고 게이트 0.5 mm 하한도 못 넘는다).

2. **`_min_clearance` 가 AABB 분리거리를 그대로 값으로 보고하고 있었다.**
   `shellcrank_arm ↔ pivot_boss_L_08` 참값 **2.181 mm** 인데 **0.002 mm** 로 보고 →
   게이트가 헛되이 FAIL. AABB 는 축정렬 **하한**이라 비스듬한 두 조각에서 무너진다.
   → 하한이 임계값 밑이면 점구름 부호거리로 **정확히 재측정**. 부수로 조각쌍 전수(O(n·m))가
   점구름 1회 질의(O(n))로 바뀌어 게이트 실행이 2분+ → **3초**가 됐다.
   ⚠️ p37 의 복셀 하한(−0.787, −0.637)과 **같은 종류의 함정**이다: 하한을 값으로 읽으면 안 된다.
   같은 이유로 p37 G4/G8 도 정밀 재측정으로 통일했다.

3. **팔 여유가 거의 소진됐다.** 허브가 실체를 갖자
   G4 2.491 → **0.024 mm**, G9 0.325 → **0.081 mm**.
   두 값 모두 정밀 재측정 결과이므로 **측정 아티팩트가 아니라 실제 여유**다.
   PASS(≥0)이지만 FDM 으로는 인쇄 불가 수준. 원인은 셸 허브 보어 랜드(r 4.6~6.1)가
   피벗 둘레로 부풀어 link5·순정 조 쪽으로 다가간 것. **셸 형상 축은 지시 범위 밖이라
   건드리지 않았다** — 판단 필요.
