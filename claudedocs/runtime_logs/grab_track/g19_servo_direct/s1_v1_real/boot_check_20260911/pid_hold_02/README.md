# 2026-09-11 — S1 실물 어깨 P 제어 반응 데이터

**정지 초기 자세에서 P 변경에 따른 반복 반응을 관측했다.** I=0 유지, D 변경 없음. 최적 PID 선정/영구 저장/적재 시 성능 검증은 하지 않았다.

## 무엇을 했나

이동 목표와 토크는 바꾸지 않고 baseline4초 → 어깨 P8 5초 → P48 5초 → P8 5초 → P48 5초 → 어깨 P16/I0 복귀 명령 후4초 관측. 처음1.5초 연결 관측 포함29.55694초. 첫5관절 각도와 문 개방각, 팔5관절 부하 원시값을 연속 기록했다.

## 파일 사용법

- `raw.jsonl`: 유일한 원시 시리얼 기록. `tx.command`는 실제 송신, `rx_json.data`는 SDK 변환 전 수신. 타임스탬프는 PC 벽시계 `t_ns`와 단조시계 `mono_ns`; 센서 자체 시각이 아니다.
- `feedback.csv`: 모든 유효 피드백1648행. 5팔관절은 원시 radians→degrees, 문은 **180−degrees(g)**. P 열은 송신값이며 처음 두 단계 공란=미조회. tG 공란=미제공이며0으로 대체하지 않았다. 부하 필드는 서보 원시값이며 N·m나 A가 아니다.
- `result.json`, `analysis.json`: 전송 명령 목록/종료 상태와 마지막2초 재계산·반복 비교·한계.
- `plan.json`: 사전 조건·제한 및 실제 실행 소스 해시. `hw_pid_hold.py`, `hw_serial_atomic.py`는 그 해시와 대조한 실행 소스 사본. 소스 사본을 실행하면 하드웨어에 접근하므로 **분석용 재생과 구분**한다.
- **정본 시각화는 `visual_02/`**: `pid_timeseries.png`(4단 시간그래프), `pid.rrd`(전체 재생), `pid.rbl`(고정 화면 구성), `pid_rerun.png`, `decision_frames.png`, `rerun_validation.json`, `inspection.json`.
- 루트의 최초 `pid.rrd`/`pid.rbl`은 CLI PATH 누락으로 검증 중단된 후처리 시도다. 원시 실물 실험 재실행은 하지 않았다.
- `manifest_sha256.json`: 파일 무결성 목록. 별도 상위 `verify_pid.py`는 파일만 검증하며 모터를 움직이지 않는다.

재생 환경은 **rerun-sdk/CLI0.34.1**. roarm 환경의0.26.2를 사용하지 말 것. 검증·육안 확인 완료. 초기 재생 커서0초는 첫 수신 전이라 animated 패널이 비어 보일 수 있고, 오른쪽 결정 패널은 고정 시점 사본이다.

## 해석의 범위

같은 자세에서 명령 전환과 각도/부하 변화가 반복되어 **P 변경의 런타임 반응을 지지**한다. 레지스터 P·I·D와 서보 목표값을 직접 읽은 결과는 아니다. P16 복귀 이후의 부하 감소도 확인했지만, 최초 실제 P 값이나 정전 후 저장을 증명하지 않는다. 고부하 자세, 이동 중 진동, 질량 운반 성능은 별도 실험이 필요하다.
