# W11 — 계산 간격 2μs와 1μs 비교

이번 case의 신규 변수: [dt]. 실제 실행일 2026-09-12 KST. 출력 폴더 날짜는 사용자 재개 문서의 `20260911`을 유지했다.

## 1. 무엇을 왜 확인했나

W10의 저장 시점 최대 입자 속도 5.3291m/s가 계산 간격을 절반으로 줄인 한 실행에서 어떻게 달라지는지, 포획·문 정지·사후 높이맵도 함께 비교했다. **새 1μs 셀 한 번만 실행했고 W10을 재실행하지 않았다.** S1, 같은 20,000알 렌즈 더미/seed460, E5e6, 마찰·반발·구름저항, 서보·경로·제어/진단 간격·보호선을 유지했다. 설정 차이는 `timestep_s`와 신규 `render_timeline_path`뿐이다.

실물은 종료 상태 유지. 이번 세션에서 로봇 조회/구동·PID/토크·카메라·학습·A/B/C 배출·commit/push는 실행하지 않았다.

## 2. 관찰 가능한 실행 순서

1. 재개 문서와 최신 종료·실물 시간 분석·W9/W10/영상 워커 브리핑을 읽었다. 마지막 HOME는 이전 기록이며 새 조회가 아니다. W9는 W8 재생이고 W10은 별도 결과다. 실물 24g의 컵 포함 여부는 여전히 미확정이라 물성 보정에 사용하지 않았다.
2. 기존 감사의 입력 6개 해시와 설치 DEME2.4.0·Rerun SDK/CLI0.34.1을 확인했다. 호스트 GPU 연산은 정상. isaaclab의 numpy1.26.0·psutil5.9.8을 유지했고 설치하지 않았다. 입력과 W10 산출물 등158파일을 보존 목록으로 동결했다. `preflight.json`.
3. 실행 전 `PREREG.md`에 비교 항목과 한계를 기록했다. 기존 물리 코드를 새 params/out으로 실행했다. 10:12:55.181846→10:58:25.240669, 프로세스 rc0, 자동 재시도/시간가드 중단 없음. 총 경과2730.0589초(45분30.1초). `launch.json`, `terminal.json`, `cell_dt1e6_seed460/{stdout.txt,stderr.txt}`.
4. settle(재안착)→descend(하강)→close(닫힘)→lift(상승)→reclose(재닫기)를 완료했다. 기록 수는25/351/2072/137/186, 합2771시점. 실제 물리시간3.141871초, 입자64프레임. 두 조건의 엔진 초기 입자/공구/문 위치·자세 6배열은 완전 일치했다.
5. 공구 공동의 기하식으로 최종 포획 마스크를 재계산하고 알수×템플릿 질량을 원본 JSON과 대조했다. 실제 문각은 저장 메시 노드의 강체 맞춤으로 별도 확인했다. 원시 입자에서 초기/사후 높이맵을 재계산하고 시간/단계/속도/입자 전개를 대조했다. `analysis_w11.py`, `comparison.json`: `evidence_pass=true`.
6. `roarm_rl.viz_debug`로 save-only RRD를 만들고 종료 후 footer·정확 엔티티/타임라인/컴포넌트·RBL을 검증했다. 전체2771시점의 툴·접촉·9수치와64입자프레임을 RRD에서 읽어 표시 정밀도에서 원자료와 정확히 대조했다. 정상 W10 대조는 PASS, 기대 고정부 좌표만 메모리에서1mm 옮긴 음성 대조는 해당 엔티티만 FAIL했다. 원자료 변경 없음.
7. 헤드리스 Rerun 화면·명목/실제 축·높이맵/전시점 곡선 PNG4개를 실제로 열어 확인했다. 파일과 SHA256, 구체적 관찰/한계는 `inspection.json`. 큰 영상은 만들지 않았다.

`servo_stall`은 저항 토크가 기존 `1.96×0.9=1.764N·m` 선에 도달해 문을 멈춘 것이다. `pinch_guard`는 툴 단일 접촉력이 기존 `3N` 선을 넘어서 멈춘 것이다. W11 재닫기는 토크선 아래에서 접촉력3.0089N 때문에 정지했다. **보호선을 변경한 결과가 아니며, 두 번 모두 토크로 정지하던 양상은 유지되지 않았다.** 이 진단은 실물 펠릿 파손을 측정한 것이 아니다. 코드 `sim_deme_scoop_s1.py:733` 및 결과 `door.stops[1]`.

저장 속도 경고 개선의 사전 기준(완주·최대<5m/s·초과0)은 충족했다. 그러나 W11에도 **재닫기 2m/s 속도 이벤트와 2N 접촉력 진단 이벤트**는 남는다. 파일명이 `diverge_event*`여도 `diverged=false`와 모순되지 않는다. 해당 파일은 낮은 진단 문턱에서 저장하는 이벤트 덤프이지 반드시 발산 판정은 아니다. W10 최대는 close t2.529456, W11 최대는 reclose t3.119970에서 관측했다. stderr에는 두 실행 모두 기존 matplotlib 한글 글리프 경고가 있으며 물리 실패로 해석하지 않는다.

## 5. 판정과 다음 승인 경계

완료 기준은 **충족5 / 미충족0 / 포기0**이다(`GATES.md`). 원시 재계산·기존158파일/원장prefix 보존·환경핀·HEAD·문서 일치를 최종 확인했다. 샌드박스 완료검사 래퍼의 무출력 첫 시도는 FAIL로 처리했고 호스트 동일 검사에서 PASS를 확인했다. 새 물리 실행이나 기준 완화는 없었다.

**1μs 실행은 완료됐고 저장 속도 경고는 줄었지만, 포획과 재닫기 정지 원인이 달라졌다. 따라서 “2μs와 같은 물리 결과” 또는 “1μs로 수렴/문제 해결”은 입증하지 못했다.** 각 dt 한 번이므로 실행간 변동과 dt의 통계적 효과를 분리할 수 없다. 최대속도는 저장 sync 표본이며 모든 내부 계산 스텝의 상한이 아니다. 원시 초기 readback과 입력 파일은 최대1.49e-8m 차이가 있지만 두 실행의 실제 초기 배열은 정확히 같다. 포획 경계에 가까운 입자도 있어 개수는 저장 좌표 기준의 판정이다.

W11/W10 물리 루프 시간비1.4542는 이번 관측값이다. 실행 중 CPU 분석이 병행됐으므로 통제된 성능 벤치마크로 일반화하지 않는다. 원시 결과의 기본 `non_claims` 설명/상속 `_note`는 새 조건/후처리 완료를 자동 반영하지 않으므로 실제 params와 별도 Rerun 검증이 정본이다.

판정 식별자: `W11_DT1E6_COMPLETE__SAMPLED_SPEED_WARNING_REDUCED__RECLOSE_PINCH_GUARD__CONVERGENCE_UNPROVEN`.

승인된 W11은 여기서 종료한다. 기존 W10/물리 코드는 동결하며 새로운 기본 dt로 자동 승격하지 않는다. 추가 반복/dt·물성·A잔류허용/B추가제거/C통합배출은 별도 case 승인 사항이다. 현재 코드는 close/lift/reclose까지만 있어 배출·컵 질량을 검증하지 않는다. 학습과 실물 작업도 재개하지 않는다.
