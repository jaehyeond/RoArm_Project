## 0. 무엇을 왜 했나

지도교수 지적: *"히트맵 보고 매번 재관측하는 폐루프면 학습이 왜 필요하냐.
깊이 카메라로 내려다보고 제일 높은 곳 퍼면 되지 않냐."*

이 지적에는 숨은 전제가 하나 있다 — **"매번 다시 볼 수 있다"**. 이 보고서는 두 가지를
한다.

1. **P41 을 시드 5개 → 30개로 늘려** 기존 결론이 일화가 아닌지 확인한다.
   (시드 458 한 개에서만 갈렸던 결과가 프로포절 기여2의 유일한 근거였다.)
2. **그 전제를 실험 변수로 만든다.** 재관측을 `k` 스쿱마다 한 번만 허용하고
   `k = 1, 3, 5, inf` 로 쓸어, "다시 보는 것이 비싸지면 누가 먼저 무너지는가"를 잰다.
   이것이 크레인 전이(버킷이 시야를 가리고 스캔이 사이클보다 느린 상황)의
   벤치탑 대응물이다.

**신규 변수**: 관측 주기 `k` (주), belief 모형 안식각 오차 (민감도, 부).

**dug 기억을 왜 줬는가 (중요)**: 이게 없으면 낡은 지도의 최고점이 바뀌지 않으므로

조작이 된다. 기본 반경은 발자국 반폭 **29mm** 로, 기준선에 **유리한** 쪽으로 잡았다.
`oracle_2` 에는 dug 기억을 주지 **않았다** — 형상 예측이 이미 "판 자리엔 재료가 없다"를
belief 에 반영하므로, 추가로 주면 좋은 자리로 되돌아가는 것까지 금지해 방법②를
부당하게 깎는다. (이 선택의 민감도는 §4.2 에서 검증한다.)

### 통계 방법 — 부호검정(sign test)

시드마다 두 정책을 짝지어 **승/패/무**를 세고, "동전 던지기라면 이만큼 이길 확률"을
이항분포로 직접 계산한다(scipy `binomtest`, 단측). 정규성·등분산 같은 가정이 없어서
스쿱 수처럼 분포를 모르는 정수 지표에 안전하다. 무승부는 세지 않는다(표준 규약).

승패 판정 순서 — **완주가 스쿱 수보다 우선한다**:
1. 한쪽만 완주 → 완주한 쪽 승
2. 둘 다 완주 → 스쿱 수가 적은 쪽 승, 같으면 무
3. 둘 다 미완주 → 무 (보수적. 적재량으로 순위를 매기지 않는다)

**구조적 하한을 반드시 함께 읽어야 한다**: 무승부를 뺀 유효 표본 `n_eff` 에서
**전승**이어도 p 는 `0.5^n_eff` 아래로 내려가지 않는다. `n_eff < 5` 면 어떤 짝지은
부호 기반 검정으로도 0.05 를 넘길 수 없다. 즉 그 경우의 "유의하지 않음"은
**"효과가 없다"가 아니라 "이 표본으로는 가를 수 없다"**는 뜻이다.

**p-해킹 방지 규약**: 시드 수는 실행 **전에** 30개(457~486)로 고정했다. p 값이 0.05 를
넘겼다고 시드를 더 붙여 다시 계산하지 않았다. 표본을 늘리려면 목표 n 을 먼저 선언하고
전량을 새로 돌려 그 결과만 보고해야 한다.

### 2.1 읽는 법 — 프로포절에 유리한 것과 불리한 것

**유리한 것 (기여 1은 n=30 에서 확실히 선다)**
- `oracle_2` 는 30개 시드 **전부** 에서 `greedy_high` 를 이겼다 (30승 0패, p=9.3e-10).
  스쿱 수 20.17 → 14.00 (**약 30% 감소**), 실패율 0.33 → 0.00.
- `oracle_1`(양만 예측)도 26승 4패로 유의하게 이겼다 (p=3.0e-05).
- 즉 **"제일 높은 곳을 퍼면 된다"는 이 대리모델 안에서 최적이 아니다.** 이유는 P40 이
  이미 보였다 — 더미의 최고점은 대개 가장 가파른 곳이라 붕괴에 체계적으로 걸린다
  (`p40_failure_reexam.json` 시드 457: `greedy_high` 실패 7건이 **전부 avalanche**).

**불리한 것 (기여 2는 n=30 에서도 못 세운다) — 이 보고서의 핵심 negative**
- `oracle_2` > `oracle_1` 은 **4승 0패 26무, p = 0.0625 로 0.05 미달**이다.
  방향은 완벽하게 일관되지만(패배 0건) 표본이 부족하다.
- **이것은 검정을 바꿔서 해결되지 않는다.** 유효 표본이 `n_eff = 4` 이므로
  전승이어도 나올 수 있는 최소 p 가 `0.5^4 = 0.0625` 다. 짝지은 부호 기반 검정에는
  구조적 하한이 있다. (`p41b_stats.md` §표본 한계)
- 시드 5개(P41)에서 1건, 시드 30개에서 4건 — **불일치율이 약 13% 로 유지**된다.
  같은 비율이 이어진다면 `n_eff = 5` 를 넘기는 데 **시드 약 38개**가 필요하다.
  (같은 표의 마지막 열)
- **시드를 지금 더 붙여서 다시 계산하지 않았다.** p 값을 보고 표본을 늘리는 것은
  p-해킹이다. 늘리려면 목표 n 을 먼저 선언하고 전량을 새로 돌려야 한다.

**추가로 드러난 것**: `oracle_1` 의 greedy 대비 우위는 **스쿱 수**에서 나오지 완주
여부에서 나오지 않는다 (McNemar 6대4, p=0.377). 완주율까지 확실히 올리는 것은
`oracle_2` 뿐이다 (6대0, p=0.0156). 기여 2의 근거를 "완주 실패를 없앤다"로 좁히면
증거가 조금 더 선명해지지만, 그래도 `oracle_1` 대비 직접 비교는 여전히 p=0.0625 다.

### 3.2 부호검정 — 교차점

| k | `oracle_2` > `oracle_1` (형상 예측의 **추가** 이득) | `oracle_2` > `greedy_high` |
|---|---|---|
| 1 | 4승 0패 26무, **p = 0.0625** ❌ | 30승 0패, p = 9.3e-10 ✅ |

| 5 | 23승 0패 7무, p = 1.2e-07 ✅ | 30승 0패, p = 9.3e-10 ✅ |
| inf | 25승 0패 5무, p = 3.0e-08 ✅ | 30승 0패, p = 9.3e-10 ✅ |

**교차점 = k = 3** (`p42_crossover.json` 의 `k_first_significant_oracle2_over_oracle1`).

### 3.3 이것이 교수님 지적에 대한 답이다

- **k=1 (매번 다시 볼 수 있다) 에서는 교수님이 대체로 옳다.** 형상 예측의 *추가* 이득이
  통계적으로 잡히지 않는다 (p=0.0625). 양만 예측해도 거의 같은 성능이 나온다.
- **재관측을 3 스쿱마다 한 번으로 줄이는 순간 갈린다** (p=4.8e-07).
- **한 번만 보고 끝까지 가야 하면 교수님 안은 완주율 0.000 이다.** 30개 시드 전부
  `consecutive_failure_limit` 로 중단됐다 (`p42_observation_budget.json`, terminal_reason
  분포: `target_reached` 274 / `consecutive_failure_limit` 86, `policy_error` 0건).
- **즉 프로포절의 정당화는 "학습이 더 잘한다"가 아니라 "재관측이 비싼 크레인에서는
  예측이 필수다"로 서술해야 한다.** 이것은 슬라이드 16의 크레인 전이와 직접 연결된다.

### 3.4 예상 밖 결과 — 정직하게 보고

1. **`greedy_high` 의 완주율이 k 에 대해 단조가 아니다** (0.800 → 0.867 → 0.733 → 0.000).
   k=3 이 k=1 보다 **좋다.** 이유는 dug 기억 때문으로 보인다: 매번 다시 보는 greedy 는
   늘 현재 최고점(= 가장 가파른 곳)을 다시 골라 붕괴에 걸리는데, 낡은 지도 + "방금 판
   자리는 피한다"가 강제로 퍼뜨려 주면서 붕괴를 덜 만난다. **"항상 최신 정보가 낫다"가
   이 대리모델 안에서 성립하지 않는다.** (기여 2 와 무관한 부수 관찰이지만, 교수님 안의
   전제를 다른 각도에서 흔든다.)
2. **`oracle_1` 의 완주율도 단조가 아니다** (0.867 → 0.733 → 0.967 → 0.167).
   k=3 에서 오히려 나빠졌다가 k=5 에서 회복한다. n=30 에서 이 비단조성이 통계적으로
   의미 있는지는 검정하지 않았다 — **추세선으로 인용하면 안 된다.**
3. **`oracle_2` 가 bias=0 에서 k 에 완전히 둔감한 것(1.000 고정)은 정의상 그렇다.**
   예측 모형이 곧 실행기라서 belief 가 언제나 진짜 상태와 일치한다. **이 곡선 자체를
   "형상 예측은 재관측이 필요 없다"의 증거로 쓰면 안 된다.** 게이트 G4 의 blind_spot 에
   같은 경고를 넣어 뒀다. 의미 있는 증거는 §4 의 오차 있는 모형 결과다.

## 4. 민감도 — 임의로 정한 상수들이 결론을 만들지 않았는가

### 4.1 예측 모형이 틀렸을 때 (belief 안식각 ±4도)

`angle_of_repose` 는 PP 미실측 값이다. 예측 모형이 틀릴 수 있는 가장 정직한 자리이므로
belief 쪽 실행기의 안식각만 ±4도 흔들었다 (`--model-repose-bias-deg`).
산출물: `p42_observation_budget_bias_plus4/`, `p42_observation_budget_bias_minus4/`
(각각 `p42_observation_budget.md`, `p42_crossover.json`).

| 설정 | k=1 완주율 (g / o1 / o2) | k=inf 완주율 (g / o1 / o2) | 교차점 (o2>o1 p<0.05) |
|---|---|---|---|
| bias 0 (완전 커닝 = 상한) | 0.800 / 0.867 / 1.000 | 0.000 / 0.167 / 1.000 | **k=3** |
| bias −4도 (비관적 오차) | 0.800 / 0.733 / 0.933 | 0.000 / **0.000** / 0.900 | **k=3** |
| bias +4도 (낙관적 오차) | 0.800 / 0.533 / **0.433** | 0.000 / 0.167 / 0.867 | **k=3** |

**교차점 k=3 은 세 설정에서 모두 같다.** 모형이 완벽하든, 4도 비관적이든, 4도
낙관적이든 "3 스쿱마다 한 번"에서 형상 예측의 추가 이득이 유의해진다.

**bias −4도가 특히 중요하다**: k=inf 에서 `greedy_high` 와 `oracle_1` 이 **둘 다 완주율
0.000** 인데 `oracle_2` 만 0.900 이다. 예측 모형에 오차가 있어도, 재관측이 불가능하면
**형상을 예측하는 정책만 살아남는다.** 이것이 기여 2 의 가장 강한 근거다
(`p42_observation_budget_bias_minus4/p42_crossover.json`).

**bias +4도에서 나온 반직관적 결과 — 반드시 함께 보고할 것**: 낙관적으로 틀린 모형은
**매번 재관측할 때(k=1) 오히려 `greedy_high` 보다 나쁘다** (완주율 0.433 대 0.800,
`oracle_2` > `oracle_1` 이 5승 8패로 **역전**). 안식각을 실제보다 크게 보는 belief 는
"이 정도 경사는 안 무너진다"고 오판하는데, 매 스텝 진짜 지도로 새로 고쳐지면 **같은
오판을 계속 반복**한다. k 가 커지면 belief 가 자기 물리로 굴러가며 우연히 보수적으로
치우쳐 오히려 나아진다.
→ **"자주 다시 보면 안전하다"가 틀릴 수 있다.** 예측 모형이 낙관적으로 편향돼 있으면
재관측이 오류를 고쳐 주지 않는다. ⚠️ 다만 이 되먹임은 대리모델 완화 규칙(`_relax`)의
구체적 수식에 의존한다. **DEME 확인 전에는 물리적 주장으로 인용 금지.**

### 4.2 기준선에 준 "판 자리 기억" 반경이 결론을 만들었는가

`dug_radius_m` 은 임의 상수다. 기본 29mm(발자국 반폭) 외에 8mm·58mm 로 k=1, inf 를 다시 돌렸다.

| dug 반경 | k=1 (g / o1 / o2) | k=inf (g / o1 / o2) | 게이트 |
|---|---|---|---|
| 8mm | 0.800 / 0.867 / 1.000 | **0.000** / 0.000 / 1.000 | validity 전부 PASS |
| 29mm (기본) | 0.800 / 0.867 / 1.000 | **0.000** / 0.167 / 1.000 | validity 전부 PASS |
| 58mm | 0.800 / 0.867 / 1.000 | (무효 — 아래) | **G8 FAIL** |

- **k=1 결과는 세 반경에서 완전히 동일하다.** 설계대로다 — k=1 이면 결정 시점의 dug
  목록이 항상 비어 있다. (로그 대조로 확인: `diff` 결과 완전 일치)
- **`greedy_high` 의 k=inf 완주율 0.000 은 반경 8mm 와 29mm 에서 똑같이 나온다.**
  즉 기준선의 붕괴는 기억 반경을 인색하게 줘서 만든 것이 아니다.
- 🔴 **58mm 실행은 무효다.** 새로 만든 게이트 **G8** 이 잡았다 —
  `policy_error` 로 끝난 행이 180행 중 **60행**(`greedy_high` 30, `oracle_1` 30)이다.
  제외 마스크가 활성 셀을 전부 덮어 정책이 후보를 못 찾고 예외로 죽은 것이며,
  그 행의 "미완주"는 물리가 아니라 **마스킹 아티팩트**다. 58mm 행을 근거로
  아무것도 주장하지 않는다.
  → 원인: `p42_observation_budget.py` 의 폴백이 **실패-셀 마스크에만** 걸려 있고
  **dug 마스크에는 없다**. 3줄 수정이면 되지만, 지금 고치면 실행 중이던 실험의 의미가
  바뀌므로 손대지 않았다. **후속 작업 항목**으로 남긴다.
  (`claudedocs/runtime_logs/decision_track/p42_dugradius_058/p42_gate_report.json`)

### 4.3 이 민감도가 커버하지 못하는 것

- 예측 모형 오차를 **안식각 한 축**으로만 넣었다. 실제 모형은 밀도·발자국·입자 크기·
  재료 이력에서도 틀린다.
- ±4도는 임의값이다. PP 실측이 들어오면 오차 크기 자체가 달라진다.
- `min_fill_fraction 0.55`, `top_k 24`, `cut_depth 0.010`, 목표질량 0.10 kg 은 흔들지 않았다.

## 5. 게이트 — `GATES.md` 신설

`claudedocs/runtime_logs/decision_track/GATES.md` 에 게이트 8종을 문서화했다.
게이트 판정기는 `p42_observation_budget.py gate` 다.

게이트를 **두 종류**로 나눴다. 섞으면 "아직 주장이 안 선다"가 "코드가 깨졌다"처럼 보인다.
- **validity** — 실험이 망가지거나 조작되지 않았는가. FAIL 이면 **결과 인용 금지**.
- **claim** — 프로포절의 주장이 이 데이터로 성립하는가. FAIL 은 고장이 아니라 **보고할 사실**.
`gate` 의 종료코드는 validity 만 본다.

| ID | kind | 지키는 것 | FAIL 회귀 주입 | 주입 시 실제 관측 |
|---|---|---|---|---|
| G1 | validity | k=1 은 P41 과 완전히 같은 실험이어야 | `--model-repose-bias-deg 4` | 9건 중 3건 불일치 → FAIL |
| G2 | claim | 각 k 에서 방법②>방법① 유의 | `--n-seeds 3` | n_eff=1, p=0.5 → FAIL |
| G3 | validity | 세 정책이 실제로 다른 행동 | `--force-identical-policies` | 3칸 중 3칸 동일 → FAIL |
| G4 | validity | 관측 예산 k 준수 | `--leak-true-observation` | 9행 전부 `21 != 7` 식 불일치 → FAIL |
| G5 | validity | 세 정책이 같은 목표질량 | `--unfair-target-scale 0.9` | greedy만 0.09 → FAIL |
| G6 | claim | P41 n=30 에서 오라클>greedy 유의 | `p41b --subsample 3` | n_eff=3, p=0.125 → FAIL |
| G7 | claim | P41 n=30 에서 형상 예측 추가 이득 유의 | `p41b --subsample 3` | n_eff=1, p=0.5 → FAIL |
| G8 | validity | `policy_error` 로 죽은 행이 없는가 | `--dug-radius-m 0.058 --observe-every inf` | 180행 중 60행 policy_error → FAIL |

**8종 모두 실제로 주입해서 FAIL 을 확인했다.** 명령·출력 원문은 `GATES.md` 각 절에 있다.

**G8 은 장식이 아니었다.** 이 게이트가 실제로 §4.2 의 58mm 민감도 실행을 무효 판정했고,
그것이 없었다면 "58mm 에서도 greedy 는 완주율 0.000" 이라는 **거짓 강건성 주장**을
그대로 보고할 뻔했다.

- **G4**: 관측 **횟수만** 센다. belief 가 어떤 경로로 진짜 상태와 같아졌는지는 못 본다.

  §3 의 "oracle_2 가 k 에 둔감"은 이 사각지대의 직접적 결과다.
- **G5**: 목표질량 한 축만 본다. 실패 모델 파라미터·초기 더미·`top_k` 는 검사하지 않는다.
  또 "공정한 설정"이 "현실적인 설정"을 뜻하지 않는다.
- **G2/G6/G7**: 대리모델 안의 유의성이며, 무승부가 많으면 효과가 실재해도 검정력이 먼저
  죽는다. FAIL 을 "효과 없음"으로 읽으면 안 된다.
- **G8**: `policy_error` 만 센다. 마스킹이 지도를 **거의** 다 덮어 정책이 억지로 나쁜 칸을
  고른 경우(예외는 안 남)는 잡지 못한다. PASS 라도 dug 반경이 결과를 왜곡하지 않았다는
  보증은 아니다.

## 6. 결론 — 프로포절에 어떻게 쓰고, 어떻게 쓰면 안 되는가

### 6.1 세울 수 있는 주장 (증거 있음)

1. **"제일 높은 곳을 퍼면 된다"는 이 대리모델 안에서 최적이 아니다.**
   n=30 전 시드에서 오라클이 이겼다 (30승 0패, p=9.3e-10). 스쿱 20.17 → 14.00,
   실패율 0.33 → 0.00. 기전은 P40 이 이미 보였다 — 최고점은 대개 가장 가파른 곳이라
   붕괴에 체계적으로 걸린다. 출처: `p41_oracle_n30/p41b_stats.md`,
   `p40_failure_reexam/p40_failure_reexam.json`.
2. **재관측이 비쌀수록 형상 예측이 필요해진다.**
   재관측 주기 k=1 → 3 → 5 → inf 로 갈 때 `greedy_high` 완주율이 0.800 → 0.867 → 0.733
   → **0.000** 으로 무너지는 반면 `oracle_2` 는 1.000 을 유지한다.
   형상 예측의 *추가* 이득이 유의해지는 **교차점은 k = 3**, 그리고 이 교차점은
   예측 모형이 완벽할 때·4도 비관적일 때·4도 낙관적일 때 **모두 같다.**
   출처: `p42_observation_budget/p42_crossover.json` 및 bias ±4 폴더의 같은 파일.
3. **오차 있는 모형에서도 형상 예측만 살아남는다.**
   belief 안식각 −4도에서 k=inf 일 때 `greedy_high` 0.000, `oracle_1` 0.000,
   `oracle_2` 0.900. 출처: `p42_observation_budget_bias_minus4/p42_crossover.json`.

### 6.2 세울 수 **없는** 주장 (증거 부족 — 각색 금지)

1. 🔴 **"형상 예측이 양만 예측보다 낫다"를 매 스쿱 재관측(k=1) 조건에서 주장할 수 없다.**
   n=30 에서 4승 0패 26무, **p = 0.0625 로 0.05 미달**. 유효 표본이 4라 전승이어도
   0.0625 아래로 못 내려간다. 같은 불일치율이면 시드 **약 38개**가 필요하다.
   **표본을 사후에 늘려 다시 계산하지 않았다** (p-해킹).
2. 🔴 **어떤 수치도 "학습 성능"으로 인용 금지.** 전부 커닝(오라클) 결과이며
   **학습이 도달 가능한 상한**이다.
3. 🔴 **어떤 수치도 폴리프로필렌 값으로 인용 금지.** 안식각 32도는 임시값이다.
4. 🔴 **bias=0 에서 `oracle_2` 가 k 에 둔감한 것을 결과로 인용 금지.**
   예측 모형이 곧 실행기라서 정의상 그렇다.
5. 🔴 **58mm dug 반경 실행(`p42_dugradius_058`)의 k=inf 행은 무효.** G8 FAIL.
6. 🔴 **bias +4도의 "재관측이 잦을수록 나빠진다" 되먹임은 대리모델 완화 규칙에 의존한다.**
   DEME 확인 전에는 물리적 주장으로 쓰지 말 것.

### 6.3 다음에 할 일 (제안 — 결정은 코디네이터/사용자)

- **A. 사전 선언 후 시드 38개 재실행.** k=1 에서의 기여 2 를 통계로 세우려면 이 방법뿐이다.

- **B. `dug` 마스크 폴백 3줄 추가** (`p42_observation_budget.py`, 실패-셀 마스크에만
