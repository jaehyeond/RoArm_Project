## 1. g9 실패 규명 — 게이트 13종이 전부 PASS 인 채 넘어갔다

층 210(z 42 mm) 부근에서 부품이 전도했고 프린터는 감지하지 못해 계속 허공에 뽑았다.
**P1S 에는 X1 의 AI 실패 감지가 없다** — 개루프다.
판에는 바닥판+브림이 **남아 있었다**(사용자 확인: *"판은 붙어있긴했는데, 이전처럼 안전하게
붙어있진 않아"*) → 완전 박리가 아니라 **부분 박리 후 전도**.

### 1.1 gcode 1층 압출 부피를 브림/서포트로 갈라 재측정

```
              무게      부품접지   브림    서포트   브림비중   총접지/무게
g8 (완주)    13.99g      911     908     610     49.9%    130.0 mm²/g
g9 (실패)    17.05g      697    1031     312     59.7%    101.3 mm²/g
```

**무게 +22%, 부품 자체 접지 −24%.** 직접 원인은 D466 sidefix 가 보울 벽을 2.0→1.6 mm 로
얇게 하면서 1층 `Gap infill` 이 **365 → 17 mm²** 로 사라진 것이다. 벽이 얇아지니 메울 틈이
없어졌고 연속된 접착 피부가 윤곽선으로 바뀌었다.

### 1.2 ★ D466 의 "개선" 은 잘못된 기준과 비교됐다

D466 은 `1층접지 522 → 655 mm²` 를 개선으로 기록했다. 맞다 — **깨진 초안 대비로는.**
실제로 완주한 g8 은 **911** 이었으므로 **마지막 성공 대비로는 24% 후퇴**였다.
→ 규칙: **수정판은 직전 실패판이 아니라 마지막 성공판과 대조한다.** (D428 재판)

### 1.3 왜 게이트가 못 잡았나

`first_layer_contact_area` 의 기준은 `10 × 높이` 다. g8·g9 는 높이가 **59.5 mm 로 같아서**
임계가 595 mm² 로 고정됐고 둘 다 3~4배 여유로 통과했다. 게다가 이 게이트는 **부품을 붙잡지
않는 서포트까지 접지로 센다**(g9 은 2040 중 312 가 서포트).

## 4. 전송 게이트 6번 — 발행은 결과가 아니다 (D468 이행)

`disconnect()+loop_stop()` 을 만나 명령이 나가기 전에 끊긴 것이다. 로그에는 `Print started` 가

`send_print_job.py` 에 **게이트 6번**을 넣었다: 발행 후 연결을 유지한 채 플러시하고

g10·g11 전송에서 **둘 다 실전 작동**했다:
```
확인 중 … gcode_state=PREPARE · subtask=roarm_shell_R_g11
[OK ] 6. 출력 시작 확인
```

## 5. 출력 중 감시 — 카메라를 붙였고, 모니터를 세 번 고쳤다

MQTT 텔레메트리로는 **베드 박리를 감지할 수 없다**(g9 은 떨어진 뒤에도 `RUNNING · err=0`).
그래서 챔버 카메라(LAN 포트 6000, TLS)를 직접 붙였다 — DK 코드에 구현이 없어 신규 작성.

**실측 함정 2건**
1. 🔴 **카메라는 접속 직후 버퍼된 옛 프레임을 준다.** 판을 치운 뒤인데 치우기 전 프레임이
   나와서 "판이 안 비었다"고 오보할 뻔했다. → **첫 장은 버리고 둘째를 쓴다.**
2. 출력 중에는 프레임 간격이 길어져 한 번에 못 받는다. 타임아웃 15→45초 + 3회 재시도.

**모니터 결함 3건 (전부 같은 축 — 무엇을 종말로 볼 것인가)**

| # | 증상 | 고침 |
|---|---|---|
| 1 | 텔레메트리가 `None` 이 된 뒤 종료 조건에 안 걸려 **17시간 헛돌았다** | blank 카운트 + 종료 |
| 2 | 그 종료가 **너무 일렀다** — 5회 세고 접었는데 **직후에 진짜 오류(필라멘트 소진)가 떴다** | blank 2·5·9회에 **강제 재접속**, 12회에 종료 |
| 3 | `print_error != 0` 을 무조건 **자동 중단**으로 처리 | **알림만.** 실제 발동한 단 한 번이 복구 가능한 필라멘트 정지였고, 중단했다면 27층을 날렸다 |

★ **자동 중단이 옳았다고 검증된 사례가 아직 0건이다.** g9 의 진짜 실패(허공에 뽑기)는
`err=0` 이라 이 조건에 애초에 걸리지도 않았다.

**부수 발견**: 오늘 반복된 "MQTT 먹통" 의 상당수는 **모니터가 연결을 잡은 채 별도 조회를
연 것**이 원인이다. P1S 는 동시 MQTT 클라이언트를 제한한다. → **모니터 실행 중 별도 조회 금지.**

### 5.1 g11 필라멘트 소진 (층 27)

`print_error = 0x0300_8004`, `PAUSE`. 새 필라멘트 장착 후 `mqtt_resume()` + **결과 확인**으로
재개(`err` 0 으로 해제, 노즐 80→98°C 재승온). 완주.
⚠️ **z ≈ 5.4 mm 에 재개 이음매**가 있고 그 층 접착은 주변보다 약할 수 있다.

## 6. 희생 발 — 브림으로 못 푸는 접지를 부품 접지로 늘린다

브래킷은 자기 발이 **40.8 mm²** 뿐이라 브림 15 mm 로도 통과 점수의 **97% 가 브림**이었다.
새 게이트 자신의 `blind_spot`(*브림이 먼저 뜯긴다*)이 그대로 발현된 사례다.

`add_print_feet.py` 신설 — **출력용 STL 에만** 붙인다. 설계에 넣으면 `self_load_ratio` 같은
자중 게이트가 오염되고, 발은 잘라낼 것이라 툴 무게가 아니다.

```
             축      무게     부품접지   브림비중   mm²/g
브래킷 발없음  0.0°  11.43g      59      96.6%   153.4  ← 통과하나 믿을 수 없다
브래킷 발있음  0.0°  12.22g     891      72.6%   266.3
링크  기존    9.5°   9.46g     193      88.7%   180.9
링크  발+0°   0.0°   8.41g     868      78.9%   488.8
```

접지 정의는 `orient_for_print.py` 와 **같은 것**을 쓴다(중심 z < zmin+0.3, 법선 z < −0.7).
정의가 갈리면 한 부품에 두 숫자가 생긴다.

⚠️ v1 은 "y≈0 좌우 다리" 를 가정해 링크(접촉이 y 30·52)에 틀린 자리에 발을 놨을 것이다.

경로 최저 z 를 보고 충돌하면 생략한다 — **링크에서 실제로 생략됐다**(z=0.00).

## 7. 링크 배향 정정 — 접지를 얻으려 기능축을 팔 이유가 없어졌다

`orientation.json` 실측:

```
linkage  before: 접지  13.8 mm²  높이 52.5  축 0°
         after : 접지 154.5 mm²  높이 54.4  축 9.46°   gain 11.2배
셸 L/R, 브래킷 : before == after (회전 0)
```

**배향기가 접지 11.2배를 얻으려고 힌지축을 9.46° 판 것**이다. 그 축에는 기어·핀·로드아이가
동축이라 기울이면 보어가 타원이 되고 이빨이 층으로 쌓인다.

발이 생겼으므로 축을 팔 필요가 없다 → **축 0° + 발**: 접지 193→868 mm², 무게 −1.05 g,
시간 **−12분**. 기울인 배향보다 **모든 축에서** 낫다.

⚠️ 원인은 `orient_for_print.py` 가 **볼록껍질 면에 눕히는 후보만** 만들기 때문이다. 힌지축에
수직인 껍질 면이 없으면 0° 를 못 낸다. **"축 정확히 정렬" 후보 추가는 미실행** — 이미 성공한
셸·브래킷 배향에 영향을 줄 수 있어 사용자 결정 대기.

| D468 | 매니페스트가 **실제 적용된 프로필** |
| D470 | 스크립트가 **실제로 읽은 STL** |

셋 다 **입력의 정체를 검사하지 않았다** = D465·D466 "의도가 아니라 결과를 봐라" 의 **입력 쪽
대응물**. 처방 3건(`source_sha256_16` 필수 · 경로는 Active Case 에서 해결 · `superseded_by` 추가)은
**아직 미구현**이다.

---

## 10. 이 세션이 주장하지 않는 것

- **수정본 셸로 물리 시뮬을 돌린 적이 없다.** §8.3 은 형상(flood fill) 판정일 뿐이다.
- **브래킷·링크는 출력하지 않았다.** 게이트만 통과했다.
- **발 자국이 바닥면에 남는다.** 두 부품의 바닥이 기능 정합면이 아닌지 **실물 확인 미완**.
- 임계 125 mm²/g 는 **성공 1·실패 1** 표본. 브림과 부품 접지를 같은 무게로 더하는데 실제로는
  **브림이 먼저 뜯긴다.**
- 베드 표면 상태(오염·Z 오프셋·습기)는 어느 게이트도 보지 못한다. g9 에서 그 축을 배제하지
  못했다 — 다만 g10·g11 이 같은 판에서 완주했으므로 주원인은 아니었다.
- `orient_for_print.py` 의 "축 정확히 정렬 후보 추가" 는 **미실행**(사용자 결정 대기).
- 출력한 셸 L/R 은 D469 §5 로 **폐기되지 않는다** — 애초 목적이 D466 ④ 의 "출력해서 손으로
  돌려본다"(사용자 결정)이며 **기구 검증에는 그대로 유효**하다.
