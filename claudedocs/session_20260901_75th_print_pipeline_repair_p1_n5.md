### 2차의 근본 원인 = JSON 타입

BambuStudio 프로필은 모든 값이 문자열인데 `brim_width`만 정수 `8`이었다.
**프로필 전체에서 유일한** 비-문자열 값이었고 슬라이서는 **오류 없이** 0으로 떨어뜨렸다.

```
프로필:  "brim_width": 8,          (int)   →  슬라이스 결과:  "0"
프로필:  "brim_type": "outer_only" (str)   →  슬라이스 결과:  "outer_only"
```
문자열로 적힌 24개 키는 전부 정확히 반영됐다. → `"8"`로 교정, 전 키 타입 검사 추가.

## 4. 🔴 사각지대 8건 — 이 세션의 핵심

```
   본 것                        못 본 것
1  브림 폭 포함 베드 안       /  브림이 켜져 있나
2  직전 작업 결말             /  지금 가동 중인가
3  프로필에 적힌 값           /  슬라이서가 실제로 쓴 값
4  브림 설정값                /  gcode 에 브림 툴패스가 있나       ← 3을 고치며 생김
5  접지 면적                  /  오버행 · 기능축 방향
6  서포트를 안 썼나           /  서포트 없이 뽑을 수 있는 형상인가
7  params 를 기록             /  재실행이 그 기록과 같은 설정인가
8  서포트가 쓰였나            /  서포트가 오버행 높이를 덮나        ← 6을 고치며 생김
```

**처방 2가지 (적용 완료)**
1. 게이트마다 `blind_spot` 필드에 "이 게이트가 못 보는 것"을 함께 적는다.
2. **FAIL을 못 내는 게이트는 게이트가 아니다** — 신설 5종 전부 실제 실패판에 회귀 주입해 FAIL 확인.

신설 게이트:
```
brim_in_gcode             gcode 안 '; FEATURE: Brim' 존재 (설정 아님)
first_layer_contact_area  1층 툴패스 적분 vs 부품 높이
functional_axis_vertical  힌지축 기울기 <= 10°
overhang_supported        서포트 **도달 높이**가 오버행을 덮나
support_stays_off_model   support_on_build_plate_only (볼트구멍 오염 방지)
```

## 5. P1 폐합 반력 — n=5

```
rep1 4.110 · rep2 2.645 · rep3 2.758 · rep4 14.734 · rep5 2.125 N
평균 5.274 ± 5.339 N · 변동계수 1.012 (표준편차 = 평균)
```
n=3 시점의 `3.171 ± 0.815`는 **표본이 작아 안정적으로 보였을 뿐**이다.
**평균으로도 대표값이 성립하지 않는다.**

### 🔴 자기정정 — "같은 설정인데 절반이 발산한다"는 판정은 틀렸다

`sim_deme_scoop.py` 하드코딩 기본값이 rep1/rep2를 만든 값과 달랐다 (26개 중 2개):
```
close_end_deg     기본 0.0  vs 실제 6.0   ← 0 은 REPORT.md 가 이미 발산한다고 문서화한 값
insert_depth_mm   기본 18.0 vs 실제 8.0   ← 2.4 입자지름만큼 더 깊이 관입
```
올바른 값으로 돌린 rep3/4/5는 **3/3 첫 시도 완주, 발산 0.** GPU 경합 가설도 함께 기각
(배타 실행에서도 잘못된 기본값이면 죽었다).

→ `force_stats()`가 모든 실행의 params + 더미 sha256 + 셸 sha256을 대조하고 하나라도
다르면 평균을 거부한다. 회귀 주입으로 FAIL 확인:
```
설정이 다른 실행이 섞여 있다 — 다른 파라미터: ['insert_depth_mm']
```
**못 보는 것: 설정 *일치*만 본다. 그 값이 옳은지는 모른다.**

## 6. 조립 구조 (사용자 질문에 답하며 확정)

**순정 가동 조는 떼지 않는다** (`stock_jaw_kept=True`, G9가 그 스윕을 검사).
코디네이터의 초기 설명("가동 조를 뗀다")은 **틀렸고 정정했다.**

```
서보 → 순정 가동 조(그대로 회전) → 조의 볼트구멍(스팬 25mm)에 체결된 서보 크랭크
     → 로드 → 셸 크랭크 → 셸_L → 26T↔26T 기어 → 셸_R
```
출력 부품 **8개** (STL 4개): 셸 L/R · 브래킷 · 서보크랭크 · 로드 · 셸크랭크 · 핀 2.

### 구동력은 남고 PLA가 모자란다

서보 스톨 1.91 N·m(ST3215 공식) → 립 힘 **94.7~122.0 N** (DEME 폐합 저항 2.1~14.7 N의 8배+).

| 부위 | 스톨 응력 | 안전율 (PLA 50 MPa) |
|---|---:|---:|
| **셸 크랭크 뿌리** | 35.8 MPa | **1.40** |
| 로드 좌굴 | — | 3.08 |
| 핀 지압 / 이중전단 | 9.9 / 8.4 | 5.05 / 5.95 |

FDM 층간은 벌크의 50~70% → **전류-제한 stall 닫힘 필수** (D452 처방에 "크랭크가 부러진다"는
두 번째 이유 추가). ⚠️ **전부 계산값. 이 링크 기구는 한 번도 물리적으로 구동된 적이 없다.**

서보 **행정 여유 0**: 0~89° 전 행정을 다 써서 셸 44.5°/개구 58 mm를 낸다.

### 조립 뷰어

`export_grab_assembly.py` → https://claude.ai/code/artifact/3af069e8-3854-4b97-8ece-c99ecb08270a
p37 `placement()`와 **같은 변환**을 그대로 옮겨 적었다(두 곳이 갈라지면 뷰어가 거짓 조립을 보여준다).
